## 1. docs/cli.md — сабкоманда `csk config build-ssh`

Место: «Группа: Сервисные», рядом с `csk config show`.
Дополнительно: в описаниях `install` / `global install` упомянуть precheck
(интерактивный промпт кандидатов на TTY; fail-closed вне TTY), в `bootstrap` —
новый опциональный вопрос про SSH-креды.

### Черновик

```markdown
### csk config build-ssh

Управляет скоупами SSH-кредов для внешних репозиториев сборки
(`go-repository-v1`). Скоуп — префикс канонической идентичности
репозитория (`host` или `host/namespace`); при установке побеждает самый
длинный совпавший скоуп, совпадение — только по границе сегмента `/`.
Флаги `--build-ssh-*` и переменные `CSK_BUILD_SSH_*` имеют приоритет над
любым скоупом конфига.

    csk config build-ssh add <scope> [--agent [SOCKET]] [--identity PATH]
                                     [--known-hosts PATH]
    csk config build-ssh list
    csk config build-ssh remove <scope>

* `--agent [SOCKET]`: использовать ssh-agent оператора; голый флаг или
  `auto` берёт живой `SSH_AUTH_SOCK` в момент установки.
* `--identity PATH`: файл идентичности. `.pub` при заданном `--agent`
  пинит, какой единственный ключ агента предъявляется (рекомендованная
  форма для ключей с passphrase); без `--agent` — приватный ключ с диска.
* `--known-hosts PATH`: переопределение known_hosts для скоупа.

Нужен минимум один из `--agent`/`--identity`. Записи хранятся в
`~/.cocoaskills/config.json` (`build_ssh`). Примеры:

    # рабочий неймспейс — агент с пином ключа
    csk config build-ssh add gitlab.example.com/portals/infra \
        --agent auto --identity ~/.ssh/work.pub

    # весь хост — незашифрованный ключ с диска
    csk config build-ssh add gitlab.example.com --identity ~/.ssh/personal

Если при `csk install` для SSH-репозитория сборки не находится ни флагов,
ни переменных, ни скоупа: на терминале оператора открывается меню
обнаруженных кандидатов (агент с числом загруженных ключей, `*.pub` из
`~/.ssh`) — выбор сохраняется в конфиг только после явного выбора скоупа;
без терминала установка падает с
`build_repository_ssh_credential_missing` и готовыми командами
`csk config build-ssh add`, собранными из тех же кандидатов.
```

## 2. docs/reference.md — раздел про build_ssh в конфиге

Место: после «Компилируемые команды» (или внутри неё подразделом).

### Черновик

```markdown
## SSH-креды внешних репозиториев сборки

Поле `build_ssh` глобального конфига хранит выбор кредов оператора по
скоупам канонической идентичности:

    "build_ssh": {
      "gitlab.example.com": {"identity": "~/.ssh/personal"},
      "gitlab.example.com/portals/infra": {
        "agent": "auto",
        "identity": "~/.ssh/work.pub"
      }
    }

Правила:

- скоуп — `host` в нижнем регистре плюс опциональные сегменты пути;
  совпадение только по целым `/`-сегментам (`portals` не покрывает
  `portals-evil`); побеждает самый длинный совпавший скоуп;
- в записи обязателен минимум один из `agent`/`identity`; обе вместе —
  pinned-agent форма (агент держит приватный ключ, `.pub` пинит
  предъявляемый ключ) — рекомендована при работающем агенте и
  канонична по Curator Protocol (третья форма authentication tail);
- приоритет источников: флаги `--build-ssh-*` > переменные
  `CSK_BUILD_SSH_*` > скоупы конфига; манифест скилла выбрать креды не
  может никогда;
- ключ мапы уникален; невалидная запись валит загрузку конфига целиком
  (fail-closed).

Выбор применяется пер-репозиторно: у одного запуска установки разные
билд-репозитории могут аутентифицироваться разными ключами. Полный
контракт: `docs/external-build-repositories.md`.
```

## 3. README.md — quickstart «приватные билд-репозитории»

Место: рядом с матрицей установки / фич. Тон — продуктовый, 6–8 строк.

### Черновик

```markdown
### Приватные репозитории сборки — за один Enter

Скиллы со компилируемыми командами собираются из отдельно запиненных
git-репозиториев. Если репозиторий приватный, при первой установке csk
сам покажет обнаруженные варианты (ssh-agent, ваши `*.pub`) — Enter на
дефолте «агент + пин ключа», выбор скоупа, готово: выбор сохраняется в
конфиг и больше не спрашивается. В CI то же самое задаётся заранее:

    csk config build-ssh add gitlab.example.com/portals/infra \
        --agent auto --identity ~/.ssh/work.pub

Пакет скилла выбрать креды не может: только оператор, только явно.
```

Сейчас всё лежит в Unreleased, а оба релиза уже вышли. Задача:

ниже.

### Черновик

```markdown
## [0.14.1] — 2026-08-22

### Добавлено

- Precheck build-SSH показывает обнаруженных кандидатов: живой
  ssh-agent (с числом загруженных ключей) и `*.pub` из `~/.ssh` — как
  интерактивное меню с дефолтом «агент + пин ключа» и как готовые
  команды `csk config build-ssh add` в fail-closed сообщении. Обнаружение
  только перечисляет материал; использование — всегда явный выбор
  оператора, сохранение — только с явным скоупом.

## [0.14.0] — 2026-08-21

### Исправлено

- Лаунчер менеджера, вызванный через симлинк пакетного менеджера
  (Homebrew, pipx, uv), канонизируется до проверки идентичности; раньше
  любая такая установка падала на go-repository-v1 с
  `build_execution_worker_identity_invalid`.
- Псевдоним `lib64 -> lib` в префиксе virtualenv больше не читается как
  два дерева пакета csk.
- Внешний статический аудит не блокирует установку на неисполняемом
  тексте внутри `vendor/` сторонних модулей (например, `curl | sh` в
  Makefile завендоренной cobra); исполняемые файлы в vendor и все
  critical-находки блокируют по-прежнему.
- Ошибка манифеста скилла из замыкания зависимостей называет скилл и
  реф-источник (`Invalid skill manifest for <skill> tag <ref> (via ...)`).
- `config.add_project` сохраняет все поля конфига (dataclasses.replace
  вместо ручной пересборки).
- `toolchain_executable_mismatch` для шимов goenv/asdf/mise дополнена
  подсказкой: положить в PATH настоящий `$(go env GOROOT)/bin`.

### Добавлено

- Скоупы `build_ssh` в глобальном конфиге: выбор SSH-кредов по префиксу
  канонической идентичности билд-репозитория, longest-prefix, пер-репо
  применение. Сабкоманда `csk config build-ssh add/list/remove`,
  precheck перед первым fetch (интерактивный промпт на TTY, fail-closed
  с готовой командой без TTY), таблица источников кредов в `--dry-run`,
  опциональный вопрос в `csk bootstrap`.
```

## 6. docs/skill-authoring.md — три добавки для авторов скиллов

1. **Шаблон резолва команд** (гасит lint
   `skill.command_resolution_contract_missing`) — вставить в §6 как
   copy-paste блок с плейсхолдером `<tool>`:

```markdown
Резолвь экспортированное имя `<tool>` один раз до первого вызова:

1. Вверх от текущей директории, затем от физического пути `SKILL.md` —
   ближайший `<tool>` в `.agents/bin` (управляемые шимы на Windows несут
   суффикс `.cmd`: `<tool>.cmd`).
2. Иначе `<tool>` в `global/bin` под домом CocoaSkills (родитель
   `CSK_CONFIG`, по умолчанию `~/.cocoaskills`), с тем же `.cmd` на
   Windows.
3. Иначе голое имя `<tool>` — только после валидации: `command -v <tool>`
   в POSIX-шеллах, `Get-Command <tool>` в PowerShell.

Если лаунчер не найден — установка неполна: сообщи об этом и остановись;
не выкачивай и не собирай CLI ад-хок.
```

2. **Антипаттерны** (новый подраздел «Чего пакет скилла не делает»),
   каждый с реальным последствием:

```markdown
- **Не коммить собранные бинарники** ни в скилл, ни в билд-репозиторий:
  они обходят trust-модель целиком (нет идентичности тулчейна, receipt,
  защищённого кеша). Тип команды `binary` не существует — манифест с ним
  не установится.
- **Не пиши в runtime-дерево установленного скилла.** Скрипт, который
  бутстрапит `.venv` рядом с собой в `~/.cocoaskills/runtime/...`,
  оставляет симлинки в защищённом дереве, и следующая установка падает с
  `unsafe transaction tree entry`. Кеши и окружения — в директориях
  пользователя (XDG, `~/.cache`), не в runtime.
- **Не держи `agents/runtime.json`.** Это легаси-фоллбэк: старые csk
  читают его вместо манифеста и превращают «нужен csk новее» в
  бессмысленный `source file not found`.
```

3. **Чек-лист перед релизом** (§13) дополнить пунктом:
   `csk skill check .` — ноль warnings (не только ok).

## 7. НОВЫЙ docs/troubleshooting.md — миграция и симптомы

Страница «симптом → причина → лечение», линк из README. Черновик целиком:

```markdown
# Диагностика установки

Симптомы ниже встречаются при обновлении со старых csk (≤0.12) и при
первом использовании компилируемых команд.

## invalid install marker … installed_at is not a UTC second timestamp

Маркер записан csk ≤0.9 (микросекундный формат). Лечение: повторный
`csk install` / `csk global install` переустанавливает скилл и
переписывает маркер. Ничего удалять вручную не нужно.

## unsafe transaction tree entry: …/runtime/<skill>/<commit>/.venv/…

Скилл прошлых версий забутстрапил виртуальное окружение прямо в
runtime-дерево, и транзакция отказывается работать поверх симлинков.
Лечение:

    rm -rf ~/.cocoaskills/runtime/*/*/.venv

Окружение пересоздастся при первом запуске команды скилла.

## go-v1 toolchain_executable_mismatch: … not below a GOROOT bin directory

В PATH первым стоит шим version-менеджера (goenv, asdf, mise) — это
скрипт-обёртка вне отпечатываемого дерева тулчейна, он не принимается.
Лечение:

    PATH="$(go env GOROOT)/bin:$PATH" csk install

## build_repository_ssh_credential_missing

Для приватного SSH-репозитория сборки не выбраны креды. На терминале
csk сам предложит обнаруженных кандидатов; в скриптах выполните команду
из текста ошибки, например:

    csk config build-ssh add <host>/<namespace> --agent auto \
        --identity ~/.ssh/<key>.pub

## Cannot resolve tag '…' … Needed a single revision

Локальный клон в skills_root не знает нового тега: `csk install`
работает по локальным рефам. Лечение: `csk upgrade` (проект) или
`csk global upgrade` — сначала fetch, затем установка.

## commands are installed in …/.agents/bin, which is not on PATH

Это не ошибка: агентские скиллы резолвят шимы напрямую. Голые команды в
интерактивном шелле — опционально: `csk shell-init --install` и
подключить напечатанный хук в профиль.
```

## 8. CONTRIBUTING.ru.md — заметка для релизёров (2 абзаца)

- Джоба `bump-homebrew-tap` живёт в release.yml и зависит от
  `publish-pypi`; её `if` обязан начинаться с `always()` — на стабильном
  релизе `publish-testpypi` скипается, и без `always()` транзитивный
  skip молча гасит бамп (уже случилось на 0.14.0).
- Homebrew-лейн distribution-smoke делает `brew trust --tap` перед
  `brew install`: Homebrew 6 отказывается грузить формулы из
  недоверенных тапов.
