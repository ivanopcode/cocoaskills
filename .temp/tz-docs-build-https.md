## 1. `README.md` — quickstart для приватных репозиториев (обязательно)

Сейчас в README есть только SSH-пример (`csk config build-ssh add …`).
Для HTTPS входа нет вообще, хотя это путь наименьшего сопротивления для
большинства: у того, кто клонирует по HTTPS, креды уже есть.

Добавить рядом с существующим SSH-блоком, тем же тоном, 6–10 строк:

- одна фраза: приватный репозиторий сборки работает и по SSH, и по HTTPS;
- для HTTPS ничего заводить не надо, если человек уже клонирует по HTTPS —
  csk предложит переиспользовать его собственные креды при первой установке
  (один Enter);
- команда для неинтерактивного случая:

  ```bash
  csk config build-https add gitlab.example.com/portals/infra --token git-credentials
  ```

- строка про CI: `CSK_BUILD_HTTPS_TOKEN` (+ `CSK_BUILD_HTTPS_HOST`, если
  билд-репозитории живут на разных хостах);
- закрывающая фраза в духе существующей: пакет скилла креды выбрать не может.

## 2. `docs/skill-authoring.md` §3 (schema v7) — транспорт больше не диктует доступ

Строки ~326–330 сейчас говорят только про SSH: «Приватные SSH-источники
требуют явного выбора кредов оператором». После этой работы утверждение
неполное и вводит автора скилла в заблуждение при выборе URL.

Переписать абзац так, чтобы он сообщал:

- в `build_repositories.*.git` допустимы обе формы, `git@host:path.git` и
  `https://host/path.git`;
- приватный репозиторий в обоих случаях требует явного выбора кредов
  оператором — скоупы `build_ssh` и `build_https` соответственно;
- выбор транспорта не решает, у кого установка получится: у SSH-варианта
  оператору нужен ключ, у HTTPS — уже существующие креды Git или токен;
- ссылка на `docs/external-build-repositories.md` за полным контрактом
  (она там уже есть, сохранить).

**Важная деталь, которую нужно упомянуть явно** (стоила полутора часов
отладки в бою): для HTTPS URL в манифесте должен нести суффикс `.git`.
Без него GitLab отвечает `301`, а fetch по контракту идёт с
`http.followRedirects=false`, поэтому установка падает
`build_repository_source_unavailable`. Это не баг менеджера, это требование
к манифесту, и его надо написать там, где авторы пишут URL.

## 3. `docs/troubleshooting.md` — две новые записи (симптом → причина → лечение)

Файл уже существует и уже держит `build_repository_ssh_credential_missing`.
Добавить в том же формате:

**`build_repository_credential_policy_invalid`** — выбранный скоуп есть, но
источник ничего не дал: не установлена переменная из `token_env`; или
`token: keyring` без сохранённого токена (`csk config build-https login
<scope>`); или `token: git-credentials`, когда у helper'а нет записи для
хоста (клонировать один раз по HTTPS либо `login`). Текст ошибки уже
называет конкретный случай — в доке дать три ветки и по команде на каждую.

**`fatal: ... The requested URL returned error: 301`** — HTTPS URL без
суффикса `.git`; fetch не следует редиректам by design. Лечение: добавить
`.git` в `build_repositories.*.git` манифеста. Симптом ловится как
`build_repository_source_unavailable`, поэтому запись должна быть найдена и
по этому коду.

Отдельно упомянуть Windows-специфику там же (или в записи про `login`):
`git credential approve` рапортует успех, даже когда Windows Credential
Manager недоступен — csk это ловит перечитыванием и говорит, что делать;
рецепты — интерактивная сессия либо `git config --global
credential.credentialStore dpapi`. Проверено на живой Windows-машине.

## Ограничения и правила

- Язык: `docs/external-build-repositories.md`, `cli.md`, `reference.md`,
  `skill-authoring.md`, `troubleshooting.md`, `README.md` — держать язык,
  который у файла уже есть; не смешивать внутри файла.
- `docs/prose-style.md` обязателен. В частности, тире как риторический
  связку запрещено «в любом языке» — на этом уже поймали в первом цикле.
- Секреты в примерах не показывать; токен нигде не принимается флагом.
- Каждый пример команды прогнать на csk из ветки и сверить с фактическим
  выводом.

## Приёмка

1. Ссылки из README ведут на новые разделы; CI-проверка ссылок зелёная.
2. Ни одного примера, которого нет в CLI (сверить с `csk config build-https --help`).
3. Автор скилла, прочитав только `skill-authoring.md`, знает про обе формы
   URL и про обязательный `.git` в HTTPS.
4. Человек с ошибкой `build_repository_credential_policy_invalid` находит в
   `troubleshooting.md` свою ветку и команду.
